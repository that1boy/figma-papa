FORMA - WINDOWS LOCAL EXPERIMENT
===============================

This package runs on a Windows x64 PC without Docker or an npm installation.
The Windows transfer ZIP includes Node.js 24 and the application dependencies.
No public download is required for basic generation and editable exports.
The GLM model is NOT included: your PC must reach your organisation's GLM API.
An installed Microsoft Edge or Google Chrome is used for web rendering.

START
-----
1. Copy the ZIP to your organisation PC and use Extract All.
   Use a writable folder such as C:\Users\YourName\Documents\FormaPilot.
   Do not run the app from inside the ZIP. Avoid a shared/synced folder.

2. Double-click 01-configure.cmd.
   It creates .env with a random app password and secrets, then opens Notepad.
   Existing configuration is preserved when you run it again.

3. To try the interface first, leave MODEL_MODE=demo.
   Demo examples are fixed and do not follow your prompts or reference images.

   For REAL generation, change these entries in .env and save:

       MODEL_MODE=glm
       GLM_BASE_URL=http://YOUR-INTERNAL-HOST:8000/v1
       GLM_MODEL=EXACT-MODEL-ID-FROM-YOUR-INFERENCE-TEAM
       GLM_API_KEY=YOUR-KEY-IF-REQUIRED

   GLM_BASE_URL is the API prefix, not the full /chat/completions URL.
   GLM_MODEL must match the deployed model ID, even if it has a custom name.
   Keep the generated SESSION_SECRET and RENDER_TOKEN.
   APP_PASSWORD is your login password; you may change it (12+ characters).
   API keys stay in this local configuration; do not paste them into support logs.

4. Double-click 02-start.cmd. Keep its window open.
   Open http://127.0.0.1:8080 and log in with APP_PASSWORD from .env.

5. In GLM mode, use Check connection, then create a project and generate.
   Try a web screen, a short presentation and a short document from real briefs.
   Add a PNG/JPEG reference to check the actual image-input path.
   Check connection alone tests text completion, not images or output quality.

STOP / RESTART
--------------
Press ENTER in the startup window, or Ctrl+C, to stop both services.
After editing .env, stop and double-click 02-start.cmd again.
Projects persist under data in the extracted folder. Back up that folder with
the app stopped. Copying the original ZIP again does not copy your projects.
Use the stop command before closing the terminal window.

WHAT WORKS WITHOUT EXTRA SOFTWARE
--------------------------------
- Text/image input to your configured GLM endpoint.
- Web prototype generation, preview, manual edits and HTML download.
- Slides/documents previewed as HTML, with editable PPTX/DOCX download.
- Version history and human evaluation records.
- Web screenshots, web PDF and model visual review when Edge/Chrome can launch.

OPTIONAL: NATIVE OFFICE RENDERING
-------------------------------
PowerPoint/Word PDF export, rendered page images and automatic visual review
of the actual Office exports need BOTH LibreOffice and Poppler. They are not
included in this ZIP. Use your organisation's approved installations.
Microsoft Office alone does not supply the renderer's conversion commands.
You can open downloaded PPTX/DOCX files in Office and review them manually.

The launcher detects LibreOffice in its usual Program Files location.
Otherwise set these .env entries to your approved executable paths:

  LIBREOFFICE_PATH="C:/Program Files/LibreOffice/program/soffice.exe"
  PDFINFO_PATH="C:/Tools/poppler/Library/bin/pdfinfo.exe"
  PDFTOPPM_PATH="C:/Tools/poppler/Library/bin/pdftoppm.exe"

Those Poppler paths are examples. Use the actual paths on your PC.
Keep all DLLs supplied with an approved Poppler installation alongside it.
The app keeps editable exports available when rendering is unavailable.

NETWORK / TROUBLESHOOTING
-------------------------
- No Docker, Python, npm, admin install or public CDN is needed for basic use.
- Local startup does not call any model. Generation calls GLM_BASE_URL.
- The launcher binds both services to 127.0.0.1; no inbound firewall opening
  is needed for access from the same PC. Other PCs cannot use this launcher.
- If execution is blocked by company policy, give this package and source to
  IT for approval. The package does not bypass Windows or company controls.
- Double-click 03-diagnostics.cmd for local setup checks; it does not call GLM.
- If ports are occupied, stop the other pilot or change PORT and RENDER_PORT
  to different unused ports in .env (for example 8090 and 8091). The launcher
  updates the local renderer URL automatically. Use the printed app URL.
- If a browser is installed in a different location, set BROWSER_EXECUTABLE
  in .env to its full .exe path. No browser download is attempted.
- If you get a corporate certificate error, ask IT for a CA bundle and set
  NODE_EXTRA_CA_CERTS="C:/Certificates/company-ca.pem" in .env, then restart.
  Do not disable certificate checking. A browser's proxy settings are not
  automatically used by this Node app; the internal API needs a usable route.
- For API errors, verify the base URL, model ID and authentication. Ask the
  inference team whether reasoning_effort=high and max_tokens=32768 are
  supported. Adjust GLM_REASONING_EFFORT / GLM_MAX_TOKENS if needed. Leave
  GLM_JSON_MODE=false unless your endpoint supports JSON response format.
- Keep this pilot's settings in .env. Pre-existing environment variables in
  your terminal can override .env; start from a clean terminal if necessary.

CONTENTS / LIMITS
----------------
runtime/node.exe: portable Windows x64 Node runtime, with its license.
node_modules/: pinned app dependencies with upstream licenses.
Full application source, tests and Docker files are included.
No personal projects, real credentials, .env file or local databases are packed.

This is a small, shared-workspace experiment: two simultaneous generation
jobs by default. It is not the 2,000-concurrent-user production deployment.
Native Windows execution does not provide the Docker renderer's container
isolation. Generated content remains restricted by the pilot's sanitizer.
Your real GLM quality and native Office rendering must be checked locally.
See README.md, VERIFICATION.md and evaluation/README.md for full details.
